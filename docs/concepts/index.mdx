## The one-paragraph version

You describe **what** should change in plain Markdown files (a _spec-driven_ workflow). **OpenSpec** gives those files a standard shape and a CLI that validates and archives them. A **coding agent** then does the implementation, guided by reusable **skills**. **tie.md** is a local app that reads all of that from your repository and shows it as one board you can supervise: who is assigned, what the agent is about to run, which files it actually changed, and which requirements have real evidence behind them. Everything stays in your files and your Git history.
