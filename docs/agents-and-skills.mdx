# Agents and skills

tie.md treats agents and skills as reusable project assets, not hidden dropdown values. For the background, see [Coding agents and skills](/docs/concepts/coding-agents-and-skills).

## Agent definitions

An MVP agent definition is plain Markdown aligned with `AGENTS.md` conventions:

- the filename provides the local identifier;
- the first heading provides the display name;
- the rest of the file is the agent's instruction text;
- configuration supplies adapter and execution bindings;
- no proprietary frontmatter is required.

```md title="agent-roster/builder.md"
# Builder

Implement only approved tasks and report verification separately.
```

Bind it to a coding-agent CLI in [configuration](/docs/configuration):

```yaml title=".tie/config.yaml"
agents:
  team-agents:builder:
    adapter: codex # codex | claude | copilot
    skills: [team-skills:testing]
    phases: [apply]
```

## Skill packages

Skills use the existing directory-plus-`SKILL.md` convention. A workspace can resolve them from its own `skills/` directory or from approved shared sources without copying them into the repository.

```md title="skills/testing/SKILL.md"
---
name: testing
description: Verify approved behavior with deterministic evidence.
---

Read [the checklist](references/checklist.md) before testing.
```

Referenced files must stay inside the skill's folder; a missing resource or a path that escapes the package makes the skill invalid for execution.

## Precedence and identity

Workspace configuration takes precedence over user configuration. Duplicate unqualified IDs are errors, not silent overrides. The interface displays:

- a qualified ID such as `workspace:builder` or `company:qa`;
- the canonical resolved path;
- workspace or shared provenance;
- current content identity;
- trust and conflict diagnostics.

## Assignment sidecar

Change-local assignment metadata lives beside the OpenSpec change:

```yaml title="openspec/changes/add-export-cancel/.tie.yaml"
version: 1
primaryAgent: team-agents:builder
reviewers: [company:qa]
allowedSkills: [team-skills:typescript, shared:test-strategy]
revision: 01900000-0000-7000-8000-000000000000
```

`revision` lets tie.md detect that someone else changed the file since you opened it. The sidecar moves with the change when OpenSpec archives it.

The sidecar ties a specific change to a specific roster agent and set of allowed skills. It does not copy the definitions or grant an agent unrestricted access, and **assigning starts nothing**: a run needs a separate handoff preview and your approval.

## Supported coding agents

| Adapter   | CLI invoked                                        | Notes              |
| --------- | -------------------------------------------------- | ------------------ |
| `codex`   | `codex exec <instruction>`                         | OpenAI Codex CLI   |
| `claude`  | `claude --print <instruction>`                     | Claude Code        |
| `copilot` | `copilot --prompt <instruction> --allow-all-tools` | GitHub Copilot CLI |

Install and sign in to each CLI yourself; tie.md never handles provider credentials. If a CLI is missing, its agents show as unavailable with the reason.

## Trust gate

Definitions outside the workspace remain inspect-only until the user approves their canonical source identity. If that identity changes later, execution is blocked until trust is reviewed again. Secrets and volatile directories are excluded from skill resource access.
