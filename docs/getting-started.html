Getting started

This guide takes you from nothing to a running Studio in about ten minutes. If terms like spec-driven development, OpenSpec, or change are new, read Concepts first—or keep it open alongside.

1. Prerequisites​

You needWhyCheck
Gittie.md reads history and the working tree (it never commits for you).git --version
OpenSpec CLI 1.16.xtie.md runs it to list, validate, and archive changes.openspec --version
A coding-agent CLI (optional)Only to run agents: Codex, Claude Code, or GitHub Copilot CLI, already signed in.codex --version, claude --version, copilot --version

Install OpenSpec with npm if you do not have it:

npm install --global @fission-ai/openspec@1.16

You can explore the board, read and edit changes, validate, and use traceability without any coding agent installed.

2. Install tie.md​

# Linux and macOS
curl -fsSL https://tie.md/install.sh | sh
# Windows (PowerShell)
irm https://tie.md/install.ps1 | iex

The installers download the native binary for your platform from the GitHub release and verify its SHA-256 checksum. Prefer npm? See the installation page for npm install --global @tie-md/cli@0.1.0 and manual downloads.

Release candidate

These commands work once v0.1.0 is published. Follow GitHub for release status.

Confirm it works:

tie --version

3. Have an OpenSpec project​

tie.md opens an existing project; it does not create one for you. If your repository has no openspec/ folder yet:

cd ~/code/my-app
openspec init

Then create a first change, either by asking your coding agent to propose one (OpenSpec installs that workflow) or by hand—see OpenSpec for the folder layout.

4. Check the workspace (optional)​

tie inspect reports what tie.md will use, without starting anything or writing a file:

$ tie inspect ~/code/my-app
Workspace: /home/you/code/my-app
OpenSpec: /home/you/code/my-app/openspec
Git: /home/you/code/my-app
Writable: yes

5. Start the Studio​

$ cd ~/code/my-app
$ tie serve
tie.md 0.1.0 serving /home/you/code/my-app
Studio: http://127.0.0.1:4317/launch?capability=…

Your browser opens the Studio. The link is one-time: it signs this browser in to the local service, which only listens on 127.0.0.1. Press Ctrl+C in the terminal to stop.

OptionEffect
tie serve <path> or --workspace <path>Open a workspace other than the current folder.
--port <n>Use another port (default 4317). A busy port is an error.
--no-openPrint the Studio link without opening a browser.
tie inspect --jsonMachine-readable workspace report.

Exit codes: 0 success, 2 usage error, 3 workspace or data-compatibility problem, 4 service could not start.

6. A first tour​

  1. Board (Changes). Each card is one OpenSpec change, placed in a column computed from its files: Draft, Ready, In progress, Review, Ready to archive. Cards show task progress, validation state, and assignment.
  2. Open a card. The change workspace has tabs for Proposal, Design, Specifications, Tasks, Agent & skills, Validation, Trace, and Activity. Toggle Rendered / Source / Split to read or edit Markdown. Checking a task updates tasks.md directly.
  3. Validate. Choose Validate on the change and see OpenSpec's exact command and diagnostics, mapped to the artifact they concern.
  4. Agents and Skills. See what tie.md found in your configured sources, and whether each is valid and trusted.
  5. Traceability. If .tie/rtm.yaml exists, see which requirements have tests and evidence—and which do not.
  6. Settings. Check the effective configuration, its origins, and choose lifecycle terminology.

Make an edit to a change file in your own editor: the Studio updates within a moment.

7. Your first supervised run (optional)​

Needs a coding-agent CLI and at least one roster agent—see Configuration and Agents and skills.

  1. In a change, open the Agent & skills tab and choose a primary agent and allowed skills. This only writes the change's .tie.yaml; nothing runs.
  2. Choose Start agent run… and read the handoff preview: agent, CLI, working directory, skills, project instructions, the full instruction, and the exact command.
  3. Choose Approve and start. Watch output in the run dock; Stop ends the agent and its child processes.
  4. Review the changed files tie.md recorded, re-run validation, and confirm any proposed trace links.

Recommended workspace layout​

my-app/
├── openspec/          ← specs and changes (OpenSpec)
├── agent-roster/      ← agent definitions, one Markdown file each (optional)
├── skills/            ← SKILL.md packages (optional)
├── .tie/
│   ├── config.yaml    ← tie.md workspace configuration (optional)
│   └── rtm.yaml       ← traceability data (optional)
├── AGENTS.md          ← project instructions for every agent (optional)
└── src/

This colocated layout is the default, not a requirement: configuration can point at shared folders elsewhere.

Troubleshooting​

  • "Workspace error" / exit code 3 – the path is not readable, or the workspace's tie.md data was written by a newer version. Run tie inspect --json for details.
  • Port already in use / exit code 4 – another process uses 4317; pass --port.
  • "OpenSpec not found" or writes blocked – install OpenSpec 1.16.x and make sure openspec is on your PATH.
  • An agent shows as unavailable – install and sign in to that CLI, then reload; the adapter is probed at startup.
  • Browser did not open – copy the Studio: link from the terminal (use it once).
