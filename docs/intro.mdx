# tie.md documentation

tie.md is a local-first visual control plane for [OpenSpec](/docs/concepts/openspec) projects. It shows your specifications, changes, agent assignments, supervised agent runs, validation, and requirements evidence in one place—without replacing the Markdown files, Git history, or coding agents that already do the work.

> **Current status:** v0.1.0 is a release candidate. Installers go live with the tagged release; follow the [application repository](https://github.com/la-rebelion/tie.md) for status.

## The short version

- **OpenSpec remains authoritative.** Lifecycle state comes from its artifacts, commands, and validation.
- **Files remain the system of record.** Markdown, YAML, and Git outlive the UI; there is no export step if you stop using tie.md.
- **Agent work is supervised.** Every run shows the agent, skills, instructions, and exact command first, and you approve it.
- **Evidence beats claims.** Changed files come from before/after snapshots; "tested" and "delivered" need real evidence, not an agent's summary.
- **Local means local.** The service listens on `127.0.0.1`, works offline, and needs no tie.md account.

## Who it is for

- **Developers** using AI coding agents who want to see and control what those agents do.
- **Tech leads and reviewers** who need to know which changes are ready, blocked, or waiting for review.
- **Product managers, analysts, and QA** who need to follow requirements to tests and releases without reading every diff.
