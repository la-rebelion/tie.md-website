Introducing tie.md: a visible knot for specification-driven work

November 9, 2026 · 2 min read
La Rebelion Labs
Building tools for independent makers

The modern development stack has plenty of powerful parts: specifications in Markdown, Git history, reusable agent instructions, focused skills, and coding agents that can implement real work.

The hard part is remembering how those parts fit together when you return tomorrow.

Great tools, loose ends​

An OpenSpec change may have a proposal, design, specifications, tasks, validation output, an assigned agent, a handful of skills, changed files, tests, and delivery evidence. Each item is inspectable. The whole picture is not.

That gap creates familiar questions:

  • Which changes are actually ready?
  • What is blocked, and by what evidence?
  • Which agent is allowed to act?
  • What changed on disk—not just in the agent's summary?
  • Which requirements are built, tested, passed, or delivered?

tie.md is an attempt to answer those questions without moving the work into another proprietary system.

A control plane, not a replacement​

OpenSpec remains authoritative. Markdown and YAML remain reviewable. Git remains Git. Agents keep their own interfaces. tie.md reads that world, presents it through a familiar board and change workspace, and places an explicit human decision before consequential actions.

The bow-tie mark tells the same story: the specification wing on the left, the agent wing on the right, and the person—the knot—in the middle.

Starting deliberately small​

The MVP targets one repository, one operator, and one mutating agent run at a time. It focuses on safe authoring, explicit assignments, supervised execution, and a bidirectional requirements traceability matrix.

The longer direction includes isolated parallel workspaces, agent teams, verification gates, scripts, MCP inventory, and Git-host integration. Those are directions, not promises. The invariant is more important: people approve consequential transitions, and the evidence remains inspectable.

Development is happening in the open at the tie.md repository.
